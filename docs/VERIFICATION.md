# Verification

What was checked in this repository, how, and what was not. Numbers quoted in [README.md](../README.md) and [SUBMISSION.md](../SUBMISSION.md) are regenerated by `python scripts/check_claims.py` from the files named below. This note does not add a second set of figures.

## Claims

`scripts/check_claims.py` reads:

- `results/real_llm_benchmark_100.json` for the model name, call count, average latency, cost, Bluffing Hardliner deal rate, and the completed-match violation count
- `results/self_play_benchmark.md` for matches per archetype, the archetype count, seed, engine savings range, and the Hard-Bargainer fixed 5%-per-round baseline
- `models/onnx_export_metrics.json` and `data/ood_split_manifest.json` for the held-out intent score and the 195-of-500 split
- `results/mi300x_roofline.json` (rebuilt by `scripts/regen_mi300x_roofline.py`) for the MI300X figure. It is a theoretical roofline lower-bound estimate, not measured. Formula: `lower_bound_seconds = (working_set_mb * 1024 * 1024) / (5.3e12)`. `working_set_mb` is the tracemalloc peak stored in `results/bench.json`. The denominator is the datasheet quote "5.3 TB/s max. peak theoretical" and the capacity quote is "Up to 192 GB HBM3" (https://www.amd.com/content/dam/amd/en/documents/instinct-tech-docs/data-sheets/amd-instinct-mi300x-data-sheet.pdf). The same check fails if a doc, `docker-compose.yml`, or `results/bench.json` states a different MI300X bandwidth, capacity, or runtime.

The deadline in SUBMISSION.md is the pack's instruction (11:00 London, BST, 18 October 2026). It is not a measurement. The script only stops that line drifting back to an older clock time.

`results/bench.json` does not name a CPU model. Judge-facing pages do not name one either.

## Decision core

Checked by `tests/test_logic_invariants.py`.

- **Expectimax.** `solver.solve` is an open-loop search: one opening and one concession schedule, scored by the expected payoff over sampled opponents. It does not re-optimise inside the round. A scalar loop uses the same samples, the same anchoring constants, and the same payoff (opponent eats 0.45 of the remaining gap, deal tolerance 0.02, break penalty 0.10, first-gap break extra above 0.32). On a 5-sample by 3-opening by 2-schedule grid the vectorised margins match that loop, and `best` is the argmax of margin minus break probability. Those constants are heuristics, documented in `src/config/heuristics.py`. They are not fitted parameters.
- **Bayesian update.** With no new offer, the posterior equals the prior at 4 decimal places, information gain is 0, and clean responsibility is 1. Responsibility stays in [0, 1]. An offer far from the prior moves the mean less than an offer near it. Deal probability stays in [0, 1]. The default four-type mix sums to 1.
- **Logrolling.** Ranked trades from `LogrollingEngine.evaluate` stay inside the mandate: price at or under the walk-away ceiling, deposit at or under `max_allowed_deposit_pct`, lead and MOQ inside their caps, and supplier surplus not negative. The status-quo baseline is not treated as a trade. Shadow prices (`lead_day_shadow_value`, capital rates, `estimated_mold_fee`, volume discount) are buyer-side settings on `CorporateMandate`, not factory quotes.
- **Reverse auction.** Openings are taken from the strategy grid, which runs up to `YOUR_CEILING` (1.35 times target). If the session ceiling is tighter, openings above that ceiling are removed before the argmax. If every grid point is above the ceiling, the offer is the ceiling and the break probability is reported as 1. A 13.0 ceiling on a 12.0 target was checked this way. Supplier names in that path are parameterised archetypes. The dashboard says so. The headline on that screen is savings versus the first-round best quote. Versus target is shown, including when that figure is negative. Savings versus the walk-away ceiling are secondary and labeled as such.
- **Intent.** Stage-1 confidence on three short strings is inside [0, 1]. That is not a new accuracy measurement. The held-out score remains the one in `models/onnx_export_metrics.json`.
- **Guardrail.** An authorised price above the object's own ceiling, and a deposit above 0.6001, raise `GuardrailViolationError`. The check is an explicit `raise`, and the same rejection still happens under `python -O`. The guardrail checks the object against itself. It does not prove the ceiling equals a separate mandate. The business deposit cap on the mandate defaults to 0.50, which is stricter than this 0.60 safety cap.
- **Circuit breaker.** `model.BREAKDOWN_TRIP_THRESHOLD` is 0.15. 0.149 does not trip. 0.15 does. `main.py`, `multi_solver.py`, and `proposal.py` use that constant. The dashboard and the extension read the same value from `GET /api/v1/heuristics`. They do not keep a second copy of the threshold.

## Human send

- Default `/round` is copilot: `pending_human_approval` is true, no buyer turn is stored, and the handler does not call `requests.post`.
- An explicit autopilot round that looks like a deal candidate does not enter `DEAL_CLOSED` and does not call Evolus. An earlier version drafted an Evolus email before `/approve`. That call is gone.
- A circuit trip returns `reply_text: null`.
- `/approve` is what records a `buyer_human_approved` turn. The extension copies with `navigator.clipboard.writeText`. After comments are removed, `content.js`, `background.js`, and `sidepanel.js` do not contain `findSendButton`, `findChatInput`, `.click(`, `execCommand`, or `InputEvent`. Background still listens on `chrome.runtime.onConnect` and `chrome.runtime.onMessage`.
- Autopilot, when asked for, still stores a local `buyer_agent` turn. That row is not a transmission to a supplier.
- `notify_deal_closed` can message the operator on WhatsApp, WeChat, or Telegram when those keys are set. The text says the contract is not sent. It is an operator alert, not the supplier offer. This checkout did not send one.

## Bugs fixed in this pass

- The trip card printed `Package Terms: Lead Time` with no label. It now uses the same "OUR proposal, not counterpart-confirmed" wording as the confirmation card. Missing lead and deposit use `CorporateMandate` defaults via a null check, not `or`.
- A supplier lead of 10 days was copied into the buyer baseline. `CorporateMandate` then rejected it (`min_desired_lead_days` is 12) and `/round` returned 500. The baseline stays the buyer default. The observed lead is stored on the turn.
- A stated `deposit_pct` was stored as null. It is stored when the request includes it.
- Auction counter-offers could sit above a session ceiling tighter than `YOUR_CEILING`, because the grid was not masked. They are masked now.
- The pre-approval Evolus email draft on an autopilot deal candidate was an outbound call. It is removed.

## No fabricated numbers outside the simulator

`scripts/check_no_fake_literals.py` walks production Python with the AST, and walks the dashboard and extension HTML/JS as text. CI runs it. `tests/test_no_fake_literals.py` runs it too.

Allowed to contain scenario floats:

- `src/config/heuristics.py`, and only when the assignment sits under a `Rationale:` comment. These are chosen safety bands, unit caps, and display quantisation. `GET /api/v1/heuristics` is what the desk and the extension display.
- `src/sim/`, including simulated mandates, archetype parameters, scripted red-team lines, and the inputs used by `verify_all.py` and `verify_live.py`.
- The self-play generator (`src/benchmark/adversaries.py`, `src/benchmark/arena.py`, `src/benchmark/ood_500_dataset.py`, `scripts/generate_ood_500.py`) and the auction simulator (`src/engine/multi_solver.py`).
- `extension/mock_chat.html`, which is labelled simulated on the page.
- Plot geometry in `src/engine/viz.py`, and the frozen early copies `benchmark_negotiation.py` and `benchmark_negotiation_v2.py`. The live solver does not import those copies.

A float that is not 0, 1, a numeric epsilon, an input cap at or above one million, a timeout, or a ×1000 / ÷1000 unit conversion is a failure anywhere else. A `¥` amount written into those files is a failure. A percent or a day-range typed into dashboard or extension HTML is a failure, because those bands have to come from the heuristics endpoint or the simulation catalogue.

What this pass moved:

- Dashboard commodity prices, lead labels, and deposit labels are no longer in `index.html` or `app.js`. The page starts at "—" and fills them from `GET /api/v1/simulation/mandates`, with a line that says they are simulated.
- The trip and caution bands are no longer typed into the dashboard, the side panel, or the content script. They are filled from `GET /api/v1/heuristics`.
- The belief chart no longer draws `target × 1.08` before any offer exists.
- Auction cards show "—" when a quote is missing. They do not fall back to zero.
- Smoke-script prices live in `src/sim/smoke.py` and `src/sim/redteam.py`.

Honest exceptions the scanner does not treat as scenario data:

- Integers: counts, seeds, HTTP statuses, day defaults on a pydantic field, loop bounds.
- Tests. They assert behaviour and may use the simulated mandates.
- `results/*.json` and the markdown under `docs/`. Those are measured outputs or write-ups. `scripts/check_claims.py` keeps README and SUBMISSION numbers tied to the result files, and it fails if an MI300X bandwidth, capacity, runtime, or multiplier in those pages, in `docker-compose.yml`, or under `docs/` is not the figure in `results/mi300x_roofline.json`.
- `scripts/regen_mi300x_roofline.py` is allowlisted for the two datasheet floats it cites (5.3 TB/s and the 5.2 Gbps pin rate in footnote MI300-18). It is the only place those literals are typed. The generated JSON is what the rest of the code reads.
- Comments and docstrings, including ones that say a number is not a quote.

## Customs reference

`src/market/trade_data.py` reads the UN Comtrade public preview (one period per call). `scripts/market_data.py` writes `results/market_snapshot_6601.json`. `scripts/check_market_doc.py` requires `docs/MARKET_ANALYSIS.md` to contain that snapshot's generated block.

Wiring:

- `POST /api/v1/sessions` resolves an HS code from `hs_code` or the product name and stores `market_context`.
- `GET /api/v1/market` is the same lookup. A keyword returns candidates and does not fetch.
- The dashboard engine-decision card, the extension Evidence tab, and the content-script decision deck render the block as reference only.
- `POST /api/v1/multi-auction/run` calls `simulate_reverse_auction` first, then attaches `market_context`.

Invariant: the block does not influence the solver, the recommended price, or the circuit breaker. `tests/test_market_data.py` posts the same offer to two sessions, one with a caller-supplied unit value, and requires the same `recommended_offer_price`. It also checks that a model JSON containing `recommended_price` leaves `buyer_price` null, and that two auction calls with and without an HS code return the same winning price. `solver.py` and `multi_solver.py` do not mention `market_context`.

Quantity 0 on a preview row is `not available`. An implied unit value is computed only when value and quantity both exist. Offline mode stores an explicit unavailable state.

## Not verified

The MI300X column is a theoretical roofline lower-bound estimate, not measured. The tokenfactory log in `results/real_llm_benchmark_100.json` is the committed call record; it does not store an HTTP status.
- Docker was not run. This environment has no Docker daemon.
- `scripts/verify_amd_endpoint.py` was not given a live key.
- The extension was not driven in a live Chrome window for this note. CI's extension job is a separate run.
- Seeds (`20261013` in the solver when the caller passes no generator, `42` in the self-play table) reproduce a file. They do not estimate variance.
- No factory has bought anything through this system. Auction suppliers are simulated.
